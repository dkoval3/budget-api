# BudgIT API Constitution — Open Questions

Oct 5, 2026 · @Dane

Answer the questions below. Each answer becomes a principle or constraint in `.specify/memory/constitution.md` for the BudgIT API: Java 25, Spring Boot, and Reactor `Mono`/`Flux` for a fast, fully non-blocking API.

**Sources, in order of authority:**

1. The ratified UI constitution, `budget-app/.specify/memory/constitution.md` (v1.1.0, cited below as "UI §I" etc.). It says backend rules belong in a separate backend constitution, and that where it mentions API behavior it "describes the contract the UI relies on." Section 0 lists that contract.
2. The UI open-questions answers, `budget-app/docs/constitution-open-questions.md` (cited as "UI Q1.3" etc.). Several answers there decide API internals that the ratified constitution left out. Section 1 asks whether they become API rules.

**How to answer:**

- **Priority:** P1 = decide before the first spec (it affects every feature). P2 = decide before the related feature lands. P3 = good to settle eventually.
- **Suggested default:** my recommendation. Keep it, change it, or reject it.
- **Your answer:** fill this in. Leave it blank to defer, or write "N/A" to leave it out of the constitution.

**Today:** the repo is a bare Maven project. `pom.xml` sets Java 25 but has no Spring Boot parent or dependencies, `src/` is empty, and `.specify/memory/constitution.md` is the unfilled Spec Kit template. On the UI side, every function in `src/crud-api.ts` is a placeholder, so no endpoint shapes exist yet.
